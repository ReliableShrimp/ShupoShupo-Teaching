# Chapter 1: Coordinates and Vectors

## Cartesian Coordinates, Distance, and Midpoint Formulas in 2D / 3D / n-D

Analytic geometry (a.k.a. coordinate geometry) is a branch of math that connects algebra to geometry, making you think about geometry not just as shapes, but as dots on the coordinate plane (x, y) that can be represented by algebraic formulas.

The pivotal idea behind analytic geometry is that every point on the plane is a unique pair of real numbers, and every geometric locus (a line, surface, or curve) corresponds to an algebraic formula.

...The further we go, the more this idea will click, so don't worry :3

Just for now...

We already know what a Cartesian coordinate plane looks like — in case we forgot (I'm sure we didn't):

```
Coordinate Plane

	        y

            ^
      II    │    I
            │
────────────┼──────────> x
            │
      III   │    IV
            |
```

That's where all of our figures will be drawn.

The middle point — where these two lines intersect — is called the **origin** (0, 0), which literally means (x, y).

If we had the point (3, 5), we'd move 3 blocks along x (right) and 5 along y (up).

```
        y

4
3

0──────────────> x
   1 2 3
```

That's more or less what it looks like.

Everything we've done so far is in 2D — but the further we go, the more we'll end up using 3D too, which has (x, y, z). For even more dimensions, we write:

$`x_n`$ : `(x₁,x₂,x₃,...,xₙ)`

for example:

```
(2, 8, -1, 5, 0, 7)
```

We'd have to place this on a 6D space, and yes, we can't even visualize that — but for math, it's totally valid. After all, our features are just a point placed in $`nD`$ space. For example, if we have:

```
Age

```

all of these features have a value, for example:

```
Student
(18,

```

The student is just a point in a 6D space.

So when we have a dataset with 1,000+ samples, they're really just 1,000+ points in an $`nD`$ space.

> [!TIP]
> This is exactly why datasets work the way they do in ML — a dataset with 1,000+ samples is really just 1,000+ points scattered through an n-D space.

Now let's say we have:

```
A(x₁,y₁)

B(x₂,y₂)
```

We want to know something: how far apart are they? Why does that matter? Because this idea shows up in:

1. k-Nearest Neighbors (k-NN)
2. Clustering
3. Word Embeddings
4. Computer Vision
5. ...

So let's work through an example of finding the distance.

Let's say A(x₁,y₁) = A(5, 4), and B(x₂,y₂) = B(7, 5).

<img width="700" height="500" alt="image" src="https://github.com/user-attachments/assets/cf2ac76e-976f-4c7a-a8a1-9efdb08c4e25" />

These are the points we currently have, so now we can use the formula to find the distance between them:

```math
d^2 = (\Delta x)^2 + (\Delta y)^2 \implies d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}
```

This is clearly the Pythagorean theorem — it's just that:

```math
\Delta x = (x_2 - x_1)
```

```math
\Delta y = (y_2 - y_1)
```

So if we work through it, the solution is:

```math
d = \sqrt{(7-5)^2 + (5 -4)^2} = \sqrt{(2)^2 + (1)^2} = \sqrt{4 + 1} = \sqrt{5} \approx 2.236
```

That's the distance between the points, and now, just from two points, we also know $`\Delta x = 2`$ and $`\Delta y = 1`$.

<img width="700" height="500" alt="image" src="https://github.com/user-attachments/assets/1b531560-4951-4cac-8998-8fb310278dca" />

But there's another formula: the midpoint of two points. Why do we need it? Imagine there are two cities:

`A -------------------- B`

Where should you build a hospital? In the middle.

`A -------- H -------- B`

That's the exact same idea behind the midpoint, which we'll also use for things like cluster centers.

Since we know A(x₁,y₁) = A(5, 4), and B(x₂,y₂) = B(7, 5), we simply use the formula:

```math
M = \left( \frac{x_1 + x_2}{2}, \frac{y_1 + y_2}{2} \right)
```

So now we calculate it:

```math
M = \left( \frac{5 + 7}{2}, \frac{4 + 5}{2} \right) = M(6, 4.5)
```

That's the exact midpoint between the two points:

<img width="700" height="500" alt="image" src="https://github.com/user-attachments/assets/692d8cb5-248f-431c-9952-f1f984c71899" />


So that's how we find the distance between two points and the midpoint between them. Let's see how it works in $`3D`$ and $`nD`$.

I'll give an example for each.

For a 3D space, let's again use two points:

- $`P_1 = (2, 3, 4)`$
- $`P_2 = (8, 11, 14)`$

<img width="600" height="600" alt="image" src="https://github.com/user-attachments/assets/c1352214-92ee-4ade-bd76-51cba0eb8d2b" />


Now let's find the distance between these two points:

```math
d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2 + (z_2 - z_1)^2}
```

Now let's plug in the numbers:

```math
d = \sqrt{(8 - 2)^2 + (11 - 3)^2 + (14 - 4)^2} = \sqrt{36 + 64 + 100} = \sqrt{200} \approx 14.14
```

That's the distance, and now we also know the delta of every variable: $`\Delta x = 6`$, $`\Delta y = 8`$, and $`\Delta z = 10`$.

On the graph, it would look like:

<img width="800" height="600" alt="image" src="https://github.com/user-attachments/assets/75aae825-f46d-4b3f-a055-5b98b86bc34b" />


Now we just have the midpoint left. The formula is easy for both the distance and the midpoint, because you're just doing the same operation with different variables:

```math
M = \left( \frac{x_1 + x_2}{2}, \frac{y_1 + y_2}{2}, \frac{z_1 + z_2}{2} \right)
```

And now we just plug in the numbers:

```math
M = \left( \frac{2 + 8}{2}, \frac{3 + 11}{2}, \frac{4 + 14}{2} \right) = (5, 7, 9)
```

That's it — now we have the midpoint too:

<img width="800" height="600" alt="image" src="https://github.com/user-attachments/assets/eef8ecbc-0675-4af8-ba14-494a47725fc2" />


So that's how we find distances and midpoints in 3D space. Now... what about an $`nD`$ space?

This is easier than you might think. First, let's look at the general formulas, since they work for any 3+D dimension.

Delta:

```math
\vec{\Delta} = P_2 - P_1 = (x_{2,1} - x_{1,1},\; x_{2,2} - x_{1,2},\; \dots,\; x_{2,n} - x_{1,n})
```

Distance:

```math
d = \Vert\vec{\Delta}\Vert_2 = \sqrt{\sum_{i=1}^{n} (\Delta x_i)^2} = \sqrt{(x_{2,1} - x_{1,1})^2 + \dots + (x_{2,n} - x_{1,n})^2}
```

> [!TIP]
> If you've never seen the magnitude/norm sign before: $`\Vert \text{whatever vector or matrix} \Vert`$ just means "the magnitude of that vector or matrix."

The distance formula is identical — we're just adding more terms, but doing the same thing: $`\sqrt{(x_2 - x_1)^2 + \dots + (w_2 - w_1)^2}`$.

That's the formula for distance. Now here's the formula for the midpoint in $`nD`$:

```math
M = \frac{P_1 + P_2}{2}
```

Now let's work through an example:

- $`P_1 = (1, 4, 2, -3, 8)`$
- $`P_2 = (5, 8, -2, 1, 4)`$

First, let's find the delta:

```math
\vec{\Delta} = (5-1,\, 8-4,\, -2-2,\, 1-(-3),\, 4-8) = (4, 4, -4, 4, -4)
```

After finding the delta, we square each component, add them together, and then take the square root:

```math
d = \sqrt{4^2 + 4^2 + (-4)^2 + 4^2 + (-4)^2} = \sqrt{16 + 16 + 16 + 16 + 16} = \sqrt{80} \approx 8.944
```

That's our distance.

And finally, let's find the midpoint:

```math
M = \left( \frac{1+5}{2},\, \frac{4+8}{2},\, \frac{2-2}{2},\, \frac{-3+1}{2},\, \frac{8+4}{2} \right) = (3, 6, 0, -1, 6)
```

Visualizing this is hard, so I won't try to bring any cute points on a plane for this one.

## Vectors as Geometric Objects

So far we've treated vectors as a list of numbers, but geometrically, they're arrows defined by two fundamental properties:

1. The magnitude (length)
2. The direction

A vector doesn't really care where it starts, but we usually put its tail at the origin (0, 0).

> [!NOTE]
> A vector's identity comes only from its magnitude and direction — not its position. We just draw its tail at the origin for convenience.

(Honestly, I don't remember if I explained the next idea already, but I'll go over it again just in case.)

What does it mean to add two vectors? Adding two vectors means taking Vector A and adding it to Vector B (color me surprised). But what does that look like geometrically?

Geometrically, you have Vector A and Vector B:

<img width="600" height="600" alt="image" src="https://github.com/user-attachments/assets/9597c9ea-6ae9-43bc-842d-e219133b425a" />

Now we put the tail of one vector at the tip of the other, and add them:

```math
\vec{c} = \vec{a} + \vec{b}
```

In our case, that's:

```math
[4, 1] + [5, 6] = [9, 7]
```

That's the resulting vector.

<img width="800" height="700" alt="image" src="https://github.com/user-attachments/assets/da768f7e-494d-437d-a858-33a8558a6c28" />


This is called the **parallelogram rule** of vector addition, and we need it to understand the rest of linear algebra (even if we've already gotten through a big chunk of it without realizing we needed it).

But what happens when we multiply a vector by a scalar? The answer is simple — and I've probably already explained it, but here's a recap just in case.

Imagine we have a vector `[2, 1]`, and let's see what happens with each type of multiplication.

<img width="800" height="600" alt="image" src="https://github.com/user-attachments/assets/52cc30d0-f096-4611-81cc-f03cc5bc203d" />


The explanation is simple — let me walk you through what happened.

**The 3 Geometric Actions:**

1. **Stretch ($`c > 1`$):** $`2\vec{v}`$ pushes the arrow further out along the same line, in the original direction.
2. **Shrink ($`0 < c < 1`$):** $`0.5\vec{v}`$ pulls the arrow back closer to the origin, keeping the original direction.
3. **Flip ($`c < 0`$):** $`-1.5\vec{v}`$ spins the arrow 180° onto the opposite ray of the line, and stretches it too.

That's what scalar multiplication does.

## Dot Product

The dot product actually has two definitions — an algebraic one and a geometric one. But before we get to those, let's understand what it actually means.

The dot product answers a simple question. Imagine you have two vectors — the dot product answers:

"How much are these two vectors pointing in the same direction?"

The dot product doesn't measure direction, length, or rotation on its own. It simply measures the **alignment** of the vectors.

**Types of dot product results:**

1. **Both vectors point in almost the same direction** — we get a large, positive dot product.
2. **The vectors are perpendicular** — there's no alignment at all, so the dot product is zero.
3. **The vectors point in roughly opposite directions** — they're basically fighting each other, so the result is negative.

Now let's look at the algebraic and geometric approaches. But before that, I'll spoil the ending:

> [!TIP]
> The algebraic and geometric formulas look completely different, but they always give the same result — like measuring someone's height directly versus reading it off their passport. Different method, same answer.

### a. Algebraic Dot Product

Imagine we're given two vectors:

```
A = [2,3]

B = [5,4]
```

We can't get the angle directly — we only know the numbers. So instead, we multiply the matching components together and add up the results.

```math
\vec{a} \cdot \vec{b} = \sum_{i=1}^{n} a_i b_i = a_1 b_1 + a_2 b_2 + \dots + a_n b_n
```

In our case:

```math
2 \times 5 + 3 \times 4 = 22
```

A large positive result like this means the two vectors point in almost the same direction. This process is also exactly what PyTorch, TensorFlow, and Julia do internally under the hood.

### b. Geometric Dot Product

Here we're interested in a different question: "What is the angle between the vectors?"

Imagine this: you're out running, and you start wondering how much the wind is actually helping you.

```
            b (wind)
           ↗
          /
         /
        / 
       /) θ
O────────────────► a (You running)
```

Here we use the formula:

```math
\vec{a} \cdot \vec{b} = \Vert\vec{a}\Vert \Vert\vec{b}\Vert \cos\theta
```

Basically: "How much does the wind actually help your race?"

Three factors determine the result:

- **How fast are you running? ($`\Vert\vec{a}\Vert`$)** — if you're sprinting, any boost or resistance from the wind affects your performance a lot more.
- **How strong is the wind? ($`\Vert\vec{b}\Vert`$)** — a gentle breeze barely matters; a really strong wind has a massive effect.
- **What's the angle? ($`\theta`$)** — direction is everything. A wind at your back helps; a wind in your face slows you down a lot.

The cosine term matters more than anything else, because it literally tells you: "What part of vector B is working in the same direction as vector A?"

There are a few key results worth knowing:

- $`\cos{0^o}`$: a pure tailwind. It blows directly at your back, speeding you up at maximum effect ($`\cos(0) = 1`$, or 100% efficiency — the max possible):

```
Wind ───────► 
You ───────►   
```

- $`\cos{60^o}`$: this wind is acting at about 50% effectiveness. It blows in a bit diagonally ($`\cos(60) = 0.5`$, or 50% efficiency):

```
Wind  ↗ 
You ───────►
```

- $`\cos{90^o}`$: the wind doesn't help you at all — it's blowing straight up, forming a right angle ($`\cos(90) = 0`$):

```
Wind ↑ 
You ───────►  
```

Now imagine a solar panel and the sun — let's see how that affects the power it gets:

```
Direct Sunlight (Noon)        
Panel  ↑
Sun    ↓

Angle = 0°
cos(0°) = 1
[Max Power]

---

Angled Sun (3 PM)
Panel  ↑
Sun    ↙

Angle = 45°
cos(45°) ≈ 0.707
[Partial Power]

---

Sun at Horizon / Night
Panel  ↑
Sun    ←

Angle = 90°
cos(90°) = 0
[Zero Power]
```

And that wraps up the geometric side of the dot product. But let's keep going — because from here, it's only going from bad to worse.

## Lines and Planes

The first couple of topics here will be pretty useless, since we'll probably never use them again — but we'll get through them fast.

### High School Foundations

In high school, we learned the slope formula inside and out. To find it, we always used two points $`P_1(x_1, y_1)`$ and $`P_2(x_2, y_2)`$, and first calculated the slope $`m`$:

```math
m = \frac{y_2 - y_1}{x_2 - x_1}
```

Using that slope $`m`$ and any known point $`(x_1, y_1)`$, the line equation is:

```math
y - y_1 = m(x - x_1)
```

Comedia finita — that's all. Now we slowly toss this into the trash, because as soon as we're working with more than two dimensions (which is basically always), this formula becomes useless. So let's move on.

### A Line Is a Moving Point

So why do we use vectors instead of the slope (both the slang and the formula)? Because while slope is stuck in 2D, vectors — which tell us where to move — can take us to infinitely many dimensions.

A vector can travel infinitely, for example.

Let's say we start from:

$`P = (2, 1)`$

and a direction:

$`v = (3,2)`$

Now we start moving along the vector...

Walk once:

```
(2,1)

↓

(5,3)
```

Walk again:

```
↓

(8,5)
```

Again:

```
↓

(11, 7)
```

As we can see, we've started forming a line. So now we've realized something: a line is a point plus a direction.

> [!IMPORTANT]
> A line is just a point plus a direction. That's the entire idea behind the vector and parametric forms of a line.

That's the entire idea behind the vector and parametric forms.

Even if we walk in smaller steps, like:

$`v = \frac{1}{2}(3, 2) = (1.5, 1)`$

guess what — it's still a line, following the same idea, since we start from $`(2, 1)`$ and by moving in steps of $`(1.5, 1)`$ we'll still trace out a line.

So we can write this idea as a formula:

1. Our starting point = $`p`$
2. Our direction = $`v`$
3. How many copies of the direction vector we take = $`t`$

Formula:

```math
r=p+tv
```

Let's use it.

Say our starting point is (2, 6):

$`p = (2, 6)`$

Now we take 10 steps:

$`t = 10`$

And we choose our direction — 2 units right and 2 units up per step:

$`v = (2, 2)`$

So in the end, we get:

```math
r = (2, 6) + 10 \times (2, 2) = (22, 26)
```

In simple terms, this tells us: "If you walk 10 direction-vectors from the starting point, you'll arrive at the point (22, 26)."

Now let's explore the parametric form of this same formula. We just expand it out — say we:

- Start at **(2,6)**
- Walk in direction **(2,2)**
- Let $`t`$ tell us how many steps to take

We write it as:

```math
r = (2, 6) + t(2, 2)
```

Let's use our high school knowledge to expand it. First, we multiply by $`t`$:

```math
(2t, 2t)
```

Now we have:

```math
r = (2, 6) + (2t, 2t)
```

and now we just add:

```math
r = (2 + 2t, 6 + 2t)
```

That's it.

Pretty easy — but you might be asking, why do we need the same thing, just expanded? Because our machine usually wants the individual coordinates.

>

But that's not all — we also need to know how to code this in Julia:

```Julia
using LinearAlgebra

struct ParametricLine
	p::Vector{Float64}
	v::Vector{Float64}
end

(line::ParametricLine)(t::Real) = line.p + t * line.v #EXPLAIN IT

line = ParametricLine([1.0, 2.0, 3.0], [0.0, 1.0, 2.0])
#p = (1.0, 2.0, 3.0)
#v = (0.0, 1.0, 2.0)
# Here we just gave the values to p and v.
# Whenever we write line(), we're telling it what value to use for 't' — right
# now Julia sees it as line(t) = [1.0, 2.0, 3.0] + t * [0.0, 1.0, 2.0]

println("Point at t = 0: ", line(0.0))
println("Point at t = 2.5: ", line(2.5))

"""
Output:

Point at t = 0: [1.0, 2.0, 3.0]
Point at t = 2.5: [1.0, 4.5, 8.0]
"""
```

Now we can automatically see which point we're at whenever we take a certain number of steps. But the most important part here is a new Julia idea:

`(line::ParametricLine)(t::Real) =  line.p + t * line.v`

This is literally:

```math
line(t) = p + t \cdot v
```

So we first call `line`, giving it values for `p` and `v`, and after that we can call it however we want:

`line(10) = [1, 12, 23]`

`line(4) = [1, 6, 11]`

and so on...

So when we see:

```math
x(t) = x_0 + v_0t + \frac{1}{2}at^2
```

we can write it as:

```Julia

	x::Int64
	v::Float64
	a::Float64
end

(time::Kinematics)(t::Float64) = time.x + time.v * t + 1/2 * time.a * t^2

kinematics = Kinematics(1, 12.4, 3.8)

println("Kinemtatics is equal to: ", kinematics(5.0), " | when t = 5")
println("Kinemtatics is equal to:", kinematics(12.3), " | when t = 12.3")

"""
Output:

Kinemtatics is equal to: 110.5 | when t = 5

Kinemtatics is equal to:440.971 | when t = 12.3
"""
```

### What Is a Plane?

We already know 0D, 1D, and 2D. Let's build each one up and see what we can say about it.

#### 0D

We place a point...

```
•
```

That's it — a point has no length, no size, nothing. It's simply a dot. So we can understand that a single point is 0D.

#### 1D

Now imagine drawing a line:

```
<──────────────────────────────>
```

It has length! But no width — you can only move left and right, not up and down.

If we drew a vertical line instead, we'd be stuck moving up and down, but not left and right.

#### 2D

Now imagine an infinite sheet of paper:

```
 ___________________________

|                           |

|                           |

|                           |

|___________________________|
```

It has a length and a width, but no thickness. You can move up, down, left, and right.

Now we can do a lot more with it — it can be a wall, a floor, a table. They aren't quite "perfect" yet, though, since they're finite.

The biggest difference is that in 1D, you can only move in two directions:

```
────────────►
```

while on a 2D plane, we can move in every direction that lies on the sheet:

```
↖   ↑   ↗

←       →

↙   ↓   ↘
```

That's why it's 2D.

But what actually is a plane? Can we call a line (1D) a plane?

```
────────────►
```

No — because it's a line.

But what if we stick another line onto that line, so we don't have just one direction, but two?

```
      ^
      |
      │
      |
      |
      |
────────────>
```

Now we can call it a plane, because you can reach every point on the sheet. You can:

- walk right
- walk up

or:

- walk half-right
- three steps up
- left
- down

And the formula is simple:

```math
r=p+su+tv
```

We can read this as: "Choose your starting point, walk some amount in one direction, then walk some amount in another direction."

Let's work through an example. You start at $`P=(1,2)`$, then move right 1 unit — $`u = (1, 0)`$ — and up 1 unit — $`v = (0, 1)`$.

Let's say we want to do the first move 4 times and the second move 7 times:

```math
r = (1, 2) + 4(1, 0) + 7(0, 1) = (5, 9)
```

Or let's expand it in general:

```math
r=p+su+tv
```

```math
r=(x, y)+(u_1s, u_2s)+(v_1t, v_2t)
```

```math
r=(x+ u_1s + v_1t, y + u_2s + v_2t)
```

Now we have:

```math
\begin{cases} X(s, t) = x + u_1 s + v_1 t \\ Y(s, t) = y + u_2 s + v_2 t \end{cases}
```

And like we said — no mad scientist stands a chance against us.

> [!TIP]
> Think of this as GPS for a machine — a 3D game character can't reach a target point without knowing which directions to move in, and how many times to move along each one. It starts from (0, 0, 0), moves by (0.5, 0, 0.25) four times, then by (0, 2.5, 0) two times, and now it's at (2, 5, 1).

### Normal Vectors

Before we assume "normal" means cute and ordinary — in mathematics, nothing is cute and ordinary. Here, normal = **perpendicular**.

So what's a perpendicular vector? Imagine you put your phone flat on the table, then stand a pencil straight up on top of it:

```
         ▲   pencil (The normal vector)
         │
         │
    _____┴_____
   /          / (the plane)
  /__________/
```

The pencil standing straight up off the surface is the normal vector.

If you tilt the phone in any direction, the pencil tilts with it. The normal vector tells you the exact direction the surface is facing.

So if we recall:

```math
r=p+su+tv
```

we use two direction vectors to generate every point that lies on the plane.

But thanks to the normal vector, we can check whether a given point lies on the plane or above it. How? With a simple formula:

```math
(\mathbf{Q} - \mathbf{p}) \cdot n = 0
```

What does this mean?

- **$`P = (p_1, p_2, p_3)`$**: a fixed **anchor point** known to be on the plane (usually our starting point).
- **$`Q = (x, y, z)`$**: a test point anywhere in 3D space (usually given, since we want to check whether it's on the plane).
- **$`n = (a, b, c)`$**: the normal vector, perpendicular ($`90^\circ`$) to the plane.

Now let's find the displacement vector:

```math
Q - P = \begin{bmatrix} x - p_1 \\ y - p_2 \\ z - p_3 \end{bmatrix}
```

Now we take the dot product:

```math
(Q - P) \cdot n = 0
```

```math
\begin{bmatrix} x - p_1 \\ y - p_2 \\ z - p_3 \end{bmatrix} \cdot \begin{bmatrix} a \\ b \\ c \end{bmatrix} = 0
```

This is literally:

```math
a(x - p_1) + b(y - p_2) + c(z - p_3) = 0
```

or, as it's usually written:

$`ax + by + cz + d = 0`$ (where $`d = -ap_1 - bp_2 - cp_3`$).

Now let's try it out.

Let's say our anchor point is $`P = (2, 3, 1)`$ and $`n = (1, -2, 3)`$.

Let's check whether point $`Q_1 = (5, 6, 2)`$ is on the plane:

```math
Q_1 - P = \begin{bmatrix} 5 - 2 \\ 6 - 3 \\ 2 - 1 \end{bmatrix} = \begin{bmatrix} 3 \\ 3 \\ 1 \end{bmatrix}
```

Now we take the dot product:

```math
(Q_1 - P) \cdot n = (3)(1) + (3)(-2) + (1)(3) = 3 - 6 + 3 = \mathbf{0}
```

That means the point is on the plane!

Let's try another one: $`Q_2 = (4, 1, 1)`$.

We find the same kind of displacement vector:

```math
Q_2 - P = \begin{bmatrix} 4 - 2 \\ 1 - 3 \\ 1 - 1 \end{bmatrix} = \begin{bmatrix} 2 \\ -2 \\ 0 \end{bmatrix}
```

Now we find the dot product:

```math
(Q_2 - P) \cdot n = (2)(1) + (-2)(-2) + (0)(3) = 2 + 4 + 0 = \mathbf{6}
```

Wait, hold on — the result isn't 0, which means this point is above the plane, not on it.

Let's do one more test: $`Q_3 = (0, 4, -1)`$.

We find the displacement:

```math
Q_3 - P = \begin{bmatrix} 0 - 2 \\ 4 - 3 \\ -1 - 1 \end{bmatrix} = \begin{bmatrix} -2 \\ 1 \\ -2 \end{bmatrix}
```

Now we find the dot product:

```math
(Q_3 - P) \cdot n = (-2)(1) + (1)(-2) + (-2)(3) = -2 - 2 - 6 = \mathbf{-10}
```

That means this point is below the plane.

> [!TIP]
> The **sign** of $`(Q - P) \cdot n`$ tells you everything: positive means above the plane, negative means below it, and zero means the point sits exactly on the plane.

But now we have a question: by how much are they above or below the plane? To answer that, we use this formula:

```math
\text{Distance} = \frac{(Q - P) \cdot n}{\Vert n\Vert}
```

Since $`n = (1, -2, 3)`$, let's find its magnitude:

```math
\Vert n\Vert = \sqrt{1^2 + (-2)^2 + 3^2} = \sqrt{14} \approx 3.74
```

So now our table looks like this:

| **Point** | **(Q−P)⋅n** | **Position relative to plane** | **Exact perpendicular distance** |
| --- | --- | --- | --- |
| $`Q_1 = (5, 6, 2)`$ | $`0`$ | ON the plane | $`\frac{0}{\sqrt{14}} = \mathbf{0 \text{ units}}`$ |
| $`Q_2 = (4, 1, 1)`$ | $`+6`$ | ABOVE the plane | $`\frac{6}{\sqrt{14}} \approx \mathbf{1.60 \text{ units}}`$ |
| $`Q_3 = (0, 4, -1)`$ | $`-10`$ | BELOW the plane | $`\frac{\Vert -10\Vert}{\sqrt{14}} \approx \mathbf{2.67 \text{ units}}`$ |

Let's use Julia!

```Julia
using LinearAlgebra

struct PointNormalPlane
    p::Vector{Float64}
    n::Vector{Float64}
end

function evaluate_point(plane::PointNormalPlane, r::Vector{Float64})

    displace = r - plane.p

    dot_result = dot(displace, plane.n)

    signed_dot = dot_result/norm(plane.n)

    if abs(signed_dot) < 1e-9
        status = :on_plane
    elseif signed_dot > 0
        status = :above_plane
    else
        status = :below_plane
    end
    
    return status, signed_dot
end

# Anchor P = (1, 2, 3), Normal N = (0, 0, 1) pointing straight UP
plane = PointNormalPlane([1.0, 2.0, 3.0], [0.0, 0.0, 1.0])

status1, dist1 = evaluate_point(plane, [5.0, -4.0, 3.0])
println("Test 1: Status = ", status1, " | Distance = ", dist1)

status2, dist2 = evaluate_point(plane, [1.0, 2.0, 8.0])
println("Test 2: Status = ", status2, " | Distance = ", dist2)


"""
Output:


Test 1: Status = on_plane | Distance = 0.0

Test 2: Status = above_plane | Distance = 5.0
"""
```

Let me explain the parts of this code that probably need it most:

* `signed_dot = dot_result/norm(plane.n)` — this is just the distance formula:

$$
\text{Distance} = \frac{(Q - P) \cdot n}{\|n\|}
$$

where `norm` = $\|n\|$ — `norm` simply gives us the magnitude.

- `abs()` — this is just how we take the absolute value.
- `:on_plane` — using `:` creates a **symbol** in Julia. A symbol is human-readable text that's much more lightweight than a string, since Julia doesn't need to read through the whole string — it's basically a fast numerical ID under the hood.

After all of that, we can move on to the next chapter...

## Conic Sections (Circle, Ellipse, Parabola, Hyperbola)

Here we'll look at the general quadratic equation:

```math
A x^2 + B xy + C y^2 + D x + E y + F = 0
```

This formula is really powerful, because it can describe several different geometric shapes depending only on the coefficients (A, B, C, D, E, and F). The most common ones are:

- Circle
- Hyperbola
- Ellipse
- Parabola

(I won't bring in the whole zoo of conic sections here.)

Before memorizing all the formulas, let's learn how to recognize them. Keep this in mind before we start:

| Coefficient | Meaning |
| --- | --- |
| **A** | Controls the $`x^2`$ term. |
| **B** | Mixes $`x`$ and $`y`$ together ($`xy`$); this can rotate the shape. |
| **C** | Controls the $`y^2`$ term. |
| **D** | Moves (translates) the graph horizontally. |
| **E** | Moves (translates) the graph vertically. |
| **F** | A constant that changes the overall size or position of the curve. |

> [!NOTE]
> We'll ignore B for now, so don't worry about it too much.

## General Quadratic Equation

Wait, didn't we just cover the general quadratic equation? Yes — we learned one form of it:

```math
A x^2 + B xy + C y^2 + D x + E y + F = 0
```

But this form only works in 2D. The new version we're about to see works in 3D and beyond, so from here on we'll use this new form instead:

```math
\mathbf{x}^T M \mathbf{x} + \mathbf{b}^T \mathbf{x} + c = 0
```

Let's break this down piece by piece. To keep things clear, let's use an example — say that:

```math
M = \begin{bmatrix} m_{11} & m_{12} \\ m_{21} & m_{22} \end{bmatrix}, \quad \mathbf{b} = \begin{bmatrix} b_1 \\ b_2 \end{bmatrix}, \quad c
```

Let's compute this using the formula, breaking it into pieces:

**1. First step — the pure quadratic part ($`\mathbf{x}^T M \mathbf{x}`$):**

```math
\begin{bmatrix} x & y \end{bmatrix} \begin{bmatrix} m_{11} & m_{12} \\ m_{21} & m_{22} \end{bmatrix} \begin{bmatrix} x \\ y \end{bmatrix}
```

Let's solve it. Since it's all multiplication, we can choose where to start — let's multiply the matrix by the column vector first:

```math
= \begin{bmatrix} x & y \end{bmatrix} \begin{bmatrix} m_{11}x + m_{12}y \\ m_{21}x + m_{22}y \end{bmatrix}
```

Now we take the dot product with the row vector:

```math
= x(m_{11}x + m_{12}y) + y(m_{21}x + m_{22}y)
```

```math
= m_{11}x^2 + m_{12}xy + m_{21}xy + m_{22}y^2
```

```math
= m_{11}x^2 + (m_{12} + m_{21})xy + m_{22}y^2
```

That part was just basic algebra.

**2. Second step — the linear part ($`\mathbf{b}^T \mathbf{x}`$):**

```math
\begin{bmatrix} b_1 & b_2 \end{bmatrix} \begin{bmatrix} x \\ y \end{bmatrix} = b_1 x + b_2 y
```

**3. Combine everything:**

```math
m_{11}x^2 + (m_{12} + m_{21})xy + m_{22}y^2 + b_1 x + b_2 y + c = 0
```

Do we recognize something here?

```math
\begin{array}{rccccccc} \text{Matrix Expansion:} & m_{11}x^2 & + & (m_{12} + m_{21})xy & + & m_{22}y^2 & + & b_1 x & + & b_2 y & + & c & = 0 \\ \text{Scalar Form:} & A x^2 & + & B xy & + & C y^2 & + & D x & + & E y & + & F & = 0 \end{array}
```

And here's a cute observation before we move on: notice that $`B = m_{12} + m_{21}`$.

> [!TIP]
> In linear algebra, we almost always force $`M`$ to be a symmetric matrix ($`m_{12} = m_{21}`$). So if $`B = 6`$, we'd simply set $`m_{12} = 3`$ and $`m_{21} = 3`$.

Now let's try this on a 3D example, just for fun.

- **Matrix $`A`$ ($`3 \times 3`$):** $`A = \begin{bmatrix} 3 & 0 & 1 \\ 0 & 2 & 0 \\ 1 & 0 & 3 \end{bmatrix}`$
- **Vector $`\mathbf{b}`$ ($`3 \times 1`$):** $`\mathbf{b} = \begin{bmatrix} -2 \\ 4 \\ 0 \end{bmatrix}`$
- **Scalar $`c`$:** $`c = -8`$

Let's start with the pure quadratic part:

```math
A \mathbf{x} = \begin{bmatrix} 3 & 0 & 1 \\ 0 & 2 & 0 \\ 1 & 0 & 3 \end{bmatrix} \begin{bmatrix} x \\ y \\ z \end{bmatrix} = \begin{bmatrix} 3x + 0y + 1z \\ 0x + 2y + 0z \\ 1x + 0y + 3z \end{bmatrix} = \begin{bmatrix} 3x + z \\ 2y \\ x + 3z \end{bmatrix}
```

Now we take the dot product with the row vector:

```math
\mathbf{x}^T (A \mathbf{x}) = \begin{bmatrix} x & y & z \end{bmatrix} \begin{bmatrix} 3x + z \\ 2y \\ x + 3z \end{bmatrix}
```

```math
= x(3x + z) + y(2y) + z(x + 3z)
```

```math
= 3x^2 + xz + 2y^2 + xz + 3z^2
```

```math
= 3x^2 + 2y^2 + 3z^2 + 2xz
```

Now let's do the linear part:

```math
\mathbf{b}^T \mathbf{x} = \begin{bmatrix} -2 & 4 & 0 \end{bmatrix} \begin{bmatrix} x \\ y \\ z \end{bmatrix} = -2x + 4y + 0z = -2x + 4y
```

Now let's stick it all together:

```math
\underbrace{(3x^2 + 2y^2 + 3z^2 + 2xz)}_{\mathbf{x}^T A \mathbf{x}} + \underbrace{(-2x + 4y)}_{\mathbf{b}^T \mathbf{x}} + \underbrace{(-8)}_{c} = 0
```

```math
3x^2 + 2y^2 + 3z^2 + 2xz - 2x + 4y - 8 = 0
```

But what shape does this have? We'll figure that out in the next topic — using eigenvalues.

For example, this equation looks like:

Now I'll teach you something so useful that you'll be able to identify the shape from its eigenvalues alone, without even looking at the graph.

## Classifying Shapes by Eigenvalues

Why do we even need to recognize shapes using eigenvalues? Because if I give you this:

```math
4x^2+9y^2=36
```

you'll immediately say: "BROOOOO, IT'S AN ELLIPSE" — and you'd be right. But what about this one?

```math
4x^2+8xy+9y^2=36
```

That annoying $`xy`$ term makes it hard to tell what we're even looking at.

So instead of writing it in that form, we write it as:

```math
M = \begin{bmatrix} 4 & 4 \\ 4 & 9 \end{bmatrix}
```

which is basically the same as:

```math
x^TMx
```

The problem is that this matrix mixes the axes a little, because of the $`xy`$ term — but there's a way around it. Instead of leaving it as:

```math
4x^2+8xy+9y^2
```

we rewrite it as:

```math
10y_1^2+3y_2^2
```

The ugly $`xy`$ term disappears. This always happens: after rotating, every quadratic equation becomes:

```math
\lambda_1y_1^2 + \lambda_2y_2^2
```

Imagine these three possible outcomes:

**1. Ellipse**

```math
5y_1^2+2y_2^2 \quad \text{or} \quad -5y_1^2-2y_2^2
```

Both coefficients are positive (+, +) or both negative (-, -). What shape does this give? An ellipse.

**2. Hyperbola**

```math
5y_1^2 - 2y_2^2 \quad \text{or} \quad -5y_1^2 + 2y_2^2
```

Now one coefficient is negative and the other is positive: (-, +) or (+, -). What shape does this give? A hyperbola.

**3. Parabola**

```math
5y_1^2+0y_2^2 \quad \text{or} \quad 0y_1^2+2y_2^2
```

One of the coefficients is zero, while the other can be either positive or negative: (+, 0) or (-, 0). What shape does this give? A parabola.

TL;DR:

| **Eigenvalue Signs** | **Signature** | **Determinant** | **Geometric Shape** |
| --- | --- | --- | --- |
| **$`(+, +)`$ or $`(-,-)`$** | $`(2, 0, 0)`$ or $`(0, 2, 0)`$ | $`\det(A) > 0`$ | **Ellipse** |
| **$`(+, -)`$ or $`(-, +)`$** | $`(1, 1, 0)`$ | $`\det(A) < 0`$ | **Hyperbola** |
| **$`(+, 0)`$ or $`(-, 0)`$** | $`(1, 0, 1)`$ or $`(0, 1, 1)`$ | $`\det(A) = 0`$ | **Parabola** |

Now let's say we don't even care about the exact eigenvalues — we only care about their signs. That's what we call the **signature**.

For example, if we have:

```math
5y_1^2+2y_2^2
```

we can just write (2, 0, 0). This means:

- 2 positive
- 0 negative
- 0 zero

We can immediately tell this is an ellipse.

> [!TIP]
> The signature strips away the exact numbers and keeps only what matters for classification: how many eigenvalues are positive, negative, and zero.

Now for the important part: doing the same thing with 3D shapes.

Imagine our eigenvalues are all positive:

```math
(5,2,7)
```

Signature: (3, 0, 0). Since all three eigenvalues are positive, we have an **ellipsoid**.

What if we had one negative?

```math
(5,2,-4)
```

Signature: (2, 1, 0). Since one of the three eigenvalues is negative, we have a **hyperboloid**.

What if one eigenvalue is zero?

```math
(5,2,0)
```

Signature: (2, 0, 1). We get a **paraboloid**.

Now let's see how we'd compute all of this in Julia:

```Julia
using LinearAlgebra

M_mat = [
2.0 1.0 0.0
1.0 3.0 2.0
0.0 2.0 4.0
]

b_vec = [3.0, -4.0, 1.0]
x_pt = [1.0, 2.0, 3.0]

struct GQF
	M::Matrix{Float64}
	b::Vector{Float64}
end

function evaluate_gqf(gqf::GQF, x::Vector{Float64}, c::Real)
	Mx = x' * gqf.M * x
	bx = gqf.b' * x
	val = Mx + bx + c
	
	m_eigen = eigen(gqf.M)
	
	return val, m_eigen.values
end

function classify_conics(λ::Vector{Float64})
	tol = 1e-10
	
	positive = count(x -> x > tol, λ)
	negative = count(x -> x < (-tol), λ)
	zero = count(x -> abs(x) ≤ tol, λ)
	
	println("Eigenvalues: ", λ)
	println("Signature: ($positive, $negative, $zero)")
end

GQF_trial = GQF(M_mat, b_vec)
value, λ = evaluate_gqf(GQF_trial, x_pt, 5)

result = classify_conics(λ)

"""
Output:


Eigenvalues: [0.8548973087995776, 2.476023602918135, 5.669079088282288]
Signature: (3, 0, 0)
"""
```

Let me explain the trickier parts:

- `x' * ...` — in Julia, the `'` symbol means transpose.
- `eigen(...)` — this gets us both the eigenvectors and eigenvalues. Since we only need the eigenvalues here, we return just `m_eigen.values`.

> [!WARNING]
> `tol = 1e-10` acts as a safety net. In computer arithmetic, an eigenvalue is almost never *exactly* 0 — it usually comes out as a tiny number like `1.24e-16` instead, due to floating-point rounding. Without a tolerance, that near-zero value would get misclassified as "positive" or "negative" instead of "zero."

- `positive = count(x -> x > tol, λ)` — here's a closer look at this one.

Inside, we have an anonymous function (`x -> x > tol`, where `x` is the variable name we chose, and the argument after the comma — `λ` in our case — is what gets passed in). Internally, `count` does something like this:

```Julia
total = 0
for x in λ
    if (x > tol) == true
        total += 1
    end
end
return total
```

Let's work through an example:

```math
\lambda = [5.95, \;-1.2, \;0.000000000005]
```

First line, `positive = count(x -> x > tol, λ)`, does this:

1. First element `5.95`: is `5.95 > 1e-10`? $`\implies`$ `true` (matches: 1)
2. Second element `-1.2`: is `-1.2 > 1e-10`? $`\implies`$ `false`
3. Third element `5e-12`: is `5e-12 > 1e-10`? $`\implies`$ `false`

Result: `positive = 1`

Second line, `negative = count(x -> x < (-tol), λ)`, does this:

1. First element `5.95`: is `5.95 < -1e-10`? $`\implies`$ `false`
2. Second element `-1.2`: is `-1.2 < -1e-10`? $`\implies`$ `true` (matches: 1)
3. Third element `5e-12`: is `5e-12 < -1e-10`? $`\implies`$ `false`

Third line, `zero = count(x -> abs(x) ≤ tol, λ)`:

1. First element `5.95`: is `|5.95| <= 1e-10`? $`\implies`$ `false`
2. Second element `-1.2`: is `|-1.2| <= 1e-10`? $`\implies`$ `false`
3. Third element `5e-12`: is `|5e-12| <= 1e-10`? $`\implies`$ `true` (matches: 1)

That's how it actually works.

## Polar Coordinates and Parametric Curves

### Polar Coordinates

Imagine you're lost, and your friend is trying to find you, so he asks you to send your exact coordinates. There are two ways to send them. The basic way is to tell him your $`(x, y)`$.

For example: you're at (3, 4), so you'd text him: "I'm 3 meters to the east (right) and 4 to the north (up), relative to the origin."

But there's another way to answer — because if he doesn't find you and you don't make it, you might as well die with style. (Joking.) Imagine you're standing in the center of a park — instead of telling him "go 3 meters east and 4 north," you could say $`(r, \theta)`$ — "walk 5 meters at an angle of 53°."

So how do we get r?

It's simple — we just use our x and y. Since we're at (3, 4):

```math
r = \sqrt{x^2 + y^2}
```

which in our case is:

```math
r = \sqrt{3^2 + 4^2} = 5
```

So here we're just using the Pythagorean theorem.

But how do we get theta ($`\theta`$)?

The angle is always measured from the positive x-axis.

Suppose we have the point (3,3). Since it lies exactly between the x- and y-axes, the result is:

```math
\theta = 45^o \quad \text{or} \quad \frac{\pi}{4} \quad \text{(that's the result in radians)}
```

So instead of writing (3,3), we can write:

```math
(\sqrt{18}, 45^o) \quad \text{or} \quad (3\sqrt{2}, \frac{\pi}{4})
```

But what's the point of this seemingly overengineered method?

Think about drawing a circle on the coordinate plane:

```math
x^2 + y^2 = 25 \implies y = \pm\sqrt{25 - x^2}
```

Cute, but it's awkward to express any kind of rotation or radial symmetry this way. With polar coordinates, we can do the same thing in one step:

```math
r = 5
```

> [!TIP]
> That's it — we get a circle in a single line. This elegance is exactly why polar (and later, non-Euclidean) coordinate systems make certain problems so much easier to work with.

Now let's understand a part that everybody just memorizes (it uses a bit of trigonometry — if you don't know it, just memorize it, or spam it the way people spam `sklearn` without ever understanding what's actually happening).

What about converting between the two systems? We've already talked about part of this, but I haven't shown the formula for finding theta yet.

First, look at this right triangle:

```
           ● (x,y)
          /|
         / |
      r /  | y
       /θ  |
      /____|
        x
```

We already know the formula for $`\cos \theta`$:

```math
\cos \theta = \frac{\text{adjacent}}{\text{hypotenuse}}
```

In our case:

```math
\cos\theta = \frac{x}{r}
```

Now we multiply both sides by r to isolate x:

```math
r * \cos \theta = x
```

Similarly, $`\sin{\theta}`$ is:

```math
\sin \theta = \frac{y}{r}
```

```math
r * \sin \theta = y
```

We already know the distance formula:

```math
r=\sqrt{x^2+y^2}
```

and since:

```math
\tan\theta=\frac{y}{x}
```

we get:

```math
\theta = atan2(y, x)
```

Now let's do this in Julia:

```Julia
x = 3.0 
y = 4.0

r = hypot(x, y)
θ = atan(y, x)

"""
Output:

r = 5.0
θ = 0.927295...      # radians (≈53.13°)
"""

# Now if we want the answer in degrees:
θ = rad2deg(θ)

# What if we want to go from polar back to Cartesian?
# We'd do this:
r = 5.0
θ = deg2rad(53.13)

x = r * cos(θ)
y = r * sin(θ)

# Which is actually what we just studied
```

### Difference Between Distance in Normal Space and Minkowski Space

As we already know, the formula for the distance between two points is:

```math
r = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}
```

And as we've noticed, both directions contribute positively to the distance — if you go east (right) or north (up), you get farther away.

What about in 3D? The distance formula becomes:

```math
d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2 + (z_2 - z_1)^2}
```

And again, everything adds up to the distance. Whenever we:

- move right → we get farther
- move forward → we get farther
- move upward → we get farther

all of them contribute positively to the distance.

So the signature is literally (+, +, +) — meaning all dimensions contribute positively to the distance.

But what about Minkowski space? Let me first explain what that actually is.

We already know what a 2D space looks like (the Cartesian coordinate plane) and a 3D one too — these spaces describe *where* points exist.

Imagine we have a chair at `(2,5,1)` and a desk at `(7,2,4)`. This doesn't tell us the distance between them — it just tells us where each point is situated.

So now we have a question: how far is the chair from the desk? For that, we need a ruler. In math, this ruler is called a **metric** — a metric is a mathematical ruler.

But there's more than one type of ruler:

- **Ruler A:** the normal ruler that measures ordinary distance — that's **Euclidean geometry**.
- **Ruler B:** measures travel through spacetime — that's **Minkowski geometry**.
- **Ruler C:** measures distance along the Earth's surface — that's **spherical geometry**.

Here's the key difference: the space can stay the same, while the ruler changes. It's not true that Euclidean space is always limited to 3 dimensions — Euclidean space can have 1D, 100D, or 100,000D. The only thing that changes is the metric (how distance is measured — the ruler).

In Euclidean space, the distance is:

```math
d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2 + (z_2 - z_1)^2}
```

and the signature is `(+,+,+)`, since every term contributes positively to the distance.

For Minkowski space, instead of using (x, y, z), we switch to (t, x, y, z):

```math
-c^2t^2 + x^2 + y^2 + z^2
```

The signature here is `(-,+,+,+)`. This space has 4 dimensions: `(time, x, y, z)`.

In plain terms: Minkowski space isn't trying to measure how many meters separate two places. It measures how *separated two events* are. We'll run into it a lot more, so save the deep dive for month 4.

Since we've already brought up time, let's introduce it properly right now — that'll make the next step easier.

### Parametric Curves

Let's say we have a circle:

```math
x^2 + y^2 = 1
```

We understand that this tells us "this point belongs to this circle" — but it doesn't answer another question: if I walk around this circle for 1 second, where am I?

It doesn't describe:

- where we start,
- which direction we move,
- how fast we move.

It only tells us the shape.

Think about Google Maps — it has a road that looks like:

```
Start ------------------------- End
```

Let's say the formula for this is:

```math
x^2 + y^2 = 1
```

We know its shape, but we don't know where the car currently is, or when it reaches a given point.

Instead of describing the whole curve at once, we're going to describe a *moving point*. That's why we introduce a new variable — time, usually just called `t`. Now every value of `t` tells us exactly where the point is.

Suppose:

```math
x = t
```

and

```math
y = 2t
```

This is called a **parametric equation**, and the parameter here is $`t`$. Let's see what happens:

| (t) | (x) | (y) | Point |
| --: | --: | --: | --- |
| 0 | 0 | 0 | (0,0) |
| 1 | 1 | 2 | (1,2) |
| 2 | 2 | 4 | (2,4) |
| 3 | 3 | 6 | (3,6) |

The point is moving, tracing:

```
(0,0)

↓

(1,2)

↓

(2,4)

↓

(3,6)
```

These points form a line.

> [!IMPORTANT]
> We are not drawing a line — we are watching a point travel along the line. That's an easy idea to mix up, but it's the whole point of parametric curves.

What about a circle? Let's travel around it!

```math
x= \cos t\quad , \quad y=\sin t
```

When $`t = 0`$:

```math
x=\cos0^o = 1 \quad , \quad y=\sin 0^o = 0
```

so the point is (1, 0).

When $`t = \frac{\pi}{2}`$:

```math
x= \cos \frac{\pi}{2} = 0\quad , \quad y=\sin \frac{\pi}{2} = 1
```

so the point is (0, 1).

And continuing on like this, we complete a full trip around the circle.

Now let's say a particle moves according to:

```math
x = t
```

and

```math
y = t^2
```

Let's find its position at t = 0, 1, 2, and 3:

|   0 |     0 |       0 | (0,0) |

- Find the position at $`t = \frac{\pi}{2}`$

Let's work through it and see what we get.

First, let's recap what we have:

```math
x=2\cos t \quad, \quad y=2\sin t \quad , \quad z = t
```

Do we recognize this? It's the same idea as polar coordinates:

```math
x = r * \cos \theta \quad , \quad y = r * \sin\theta
```

and in our case, $`r = 2`$. From this, we can tell we're moving along a circle of radius 2.

And:

```math
z = t
```

means that as time increases, the point moves upward. So the point is doing two things at once:

- rotating around a circle,
- climbing upward.

So let's start:

**1. When $`t = 0`$:**

x = 2 \cos 0 = 2
```

```math
y = 2 \sin 0 = 0
```

```math
z = 0
```

So the position is $`(2, 0, 0)`$.

**2. When $`t = \frac{\pi}{2}`$:**

```math
\cos \frac{\pi}{2} = 0, \quad \sin \frac{\pi}{2} = 1
```

```math
z = \frac{\pi}{2}
```

so $`y = 2\sin\frac{\pi}{2} = 2`$, and the position is $`(0, 2, \frac{\pi}{2})`$.

**3. When $`t = \pi`$:**

```math
x = 2 \cos \pi = -2
```

```math
y = 2 \sin \pi = 0
```

```math
z = \pi
```

So the position is $`(-2, 0, \pi)`$.

### Arc-Length Integral

Say we went hiking, and the map looks like:

`Start ●~~~~~~~~~~~~~~~~~~~~● Finish`

The road curves. If somebody asks "how long was the hike?" — can we just compute `Finish - Start`? No, we can't, because that only measures the straight-line distance (as the crow flies).

> [!NOTE]
> Straight-line distance and arc length are not the same thing. The straight-line distance skips every curve in the road; the arc length follows every twist and turn, like a car's odometer.

Now imagine hiking up a mountain — the map looks like:

```
        Mountain

           ●
         /   \
Start ●         ● Finish
```

The straight line might be 100 meters, while the actual road is 160 meters. Why? Because the road isn't flat — it bends. That's the entire purpose of arc length. It asks:

"What is the actual length of the curve? (Start → every curve along the way → Finish. This doesn't skip anything — it tracks every turn, like a car's odometer.)"

Not:

"How far apart are the endpoints? (Start → Finish, skipping every curve, treating it as a straight line — like a crow flying from start to end.) $`d = \sqrt{(\Delta x)^2 + (\Delta y)^2}`$"

Another example: the map shows

`Home ------------------ Mall`

and says the distance is just 5 km. But the actual road looks like:

```
Home
   \
    \
     \
      \____
           \
            \____
                 \
                  Mall
```

making the real length 8 km — the arc length.

To find it, we zoom in enormously, until the curve looks like a straight line. That tiny piece of distance is written as:

```math
ds
```

If we move a tiny bit horizontally, we get $`dx`$; a tiny bit vertically, we get $`dy`$, forming a tiny triangle:

```
       ●
       |
       | dy
       |
●------●
   dx
```

That's why we need Pythagoras to find that tiny piece of distance. For now, we can write:

```math
ds = \sqrt{dx^2 + dy^2}
```

But that's only the formula for one tiny piece — we need the whole curve. So how do we add up all these tiny pieces from one end to the other? We use integrals. The total length is:

```math
L = \int ds
```

We also make this parametric, so we can move along the curve:

```math
x = x(t)
```

```math
y = y(t)
```

So we make a small substitution:

```math
dx = \frac{dx}{dt} \, dt
```

```math
dy = \frac{dy}{dt} \, dt
```

And now we put it all together:

```math
L = \int_{a}^{b} \sqrt{\left(\frac{dx}{dt}\right)^2 + \left(\frac{dy}{dt}\right)^2} \, dt
```

And now we have the full arc-length formula.

Let's see what our GPS tells us for the case we already solved:

```math
x=2\cos t \quad, \quad y=2\sin t \quad , \quad z = t
```

Let's calculate the distance between our start and finish, where $`0\le t\le 2\pi`$.

Our start: $`t = 0`$ → position $`(2, 0, 0)`$.
Our finish: $`t = 2\pi`$ → position $`(2, 0, 2\pi)`$.

Now let's measure the distance using the basic distance formula:

```math
d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2 + (z_2 - z_1)^2}
```

```math
d = \sqrt{(2 - 2)^2 + (0 - 0)^2 + (2\pi - 0)^2} = \sqrt{4\pi^2} = 2\pi \approx 6.28
```

This is the straight-line distance. Since our figure looks like:

<img width="1400" height="1044" alt="image" src="https://github.com/user-attachments/assets/418a7996-3f61-4266-b9e1-22b24b76b85f" />


we can see that this "distance" just draws a vertical line straight up to $`t = 2\pi`$, without a care in the world about the actual spiral path.

But now let's use the arc length and get the real distance:

```math
L = \int_{a}^{b} \sqrt{\left(\frac{dx}{dt}\right)^2 + \left(\frac{dy}{dt}\right)^2} \, dt
```

I won't skip any of the math steps here, since it's worth actually seeing them. First, let's find all the derivatives with respect to t:

```math
\frac{dx}{dt} = \frac{d}{dt}(2\cos t) = -2\sin t
```

```math
\frac{dy}{dt} = \frac{d}{dt}(2\sin t) = 2\cos t
```

```math
\frac{dz}{dt} = \frac{d}{dt}(t) = 1
```

Now let's square all of them:

```math
\left(\frac{dx}{dt}\right)^2 = (-2\sin t)^2 = 4\sin^2 t
```

```math
\left(\frac{dy}{dt}\right)^2 = (2\cos t)^2 = 4\cos^2 t
```

```math
\left(\frac{dz}{dt}\right)^2 = 1^2 = 1
```

Now we have:

```math
L = \int_0^{2\pi}\sqrt{4\sin^2t + 4\cos^2t + 1} \, dt = \int_0^{2\pi}\sqrt{4(\sin^2t + \cos^2t) + 1} \, dt
```

Using basic trigonometry, we know that:

```math
\cos^2 t + \sin^2 t = 1
```

so now we have:

```math
L = \int_0^{2\pi} \sqrt{4(1) + 1} \, dt = \int_0^{2\pi} \sqrt{5} \, dt
```

Since $`\sqrt{5}`$ is a constant, we can factor it out of the integral:

```math
L = \sqrt{5} \int_{0}^{2\pi} 1 \, dt
```

and now we evaluate the antiderivative:

```math
L = \sqrt{5} \Big[ t \Big]_{0}^{2\pi}
```

```math
L = \sqrt{5}(2\pi - 0) = 2\pi\sqrt{5}
```

So that's our result. To recap, going all the way from $`0`$ to $`2\pi`$:

- Straight-line distance: $`2\pi \approx 6.28`$
- Reality (arc length): $`2\pi\sqrt{5} \approx 14.05`$

So we can clearly see that reality is harsher — and more accurate.

# Chapter 3: Metrics and Transformations

## Positivity, Symmetry, and the Triangle Inequality

Before we can call just anything a "distance," there are some properties it has to satisfy. This is where the idea of a **metric** comes from.

I know we already touched on what a metric is, but let's recap briefly.

A metric is simply a mathematical definition of distance. So instead of just saying "distance is $`\sqrt{x^2 + y^2}`$," we ask a deeper question:

"Which rules must this distance obey?"

Before building a ruler, we ask ourselves:

- What should a ruler always do?
- What would make a ruler "broken"?

Those rules are the **metric axioms**.

Let's look at what a "bad ruler" would mean:

1. "The distance from A to A is 7 meters." Wait — what? Of course it can't be 7. If we haven't moved, the distance must always be 0. There's no way it's 7. This gives us our first axiom.

2. ```
   Home → School = 8 km

   School → Home = 20 km
   ```

   That's not how life works. It doesn't matter which direction you measure — if the distance from point A to point B is 2 km, the distance from B to A has to be 2 km too. That's our second axiom.

3. ```
   Home → Bakery = 2 km

   Bakery → School = 3 km

   Home → School = 20 km
   ```

   That makes no sense. Walking through the bakery can't somehow be shorter than the "shortest" route. That gives us another axiom.

From this, we can see that a proper distance measure has to satisfy some rules — and there are 4 main ones.

### 1. Positivity

The first universal rule:

**"The distance must never be negative."**

In math, that looks like:

```math
d(A, B) \ge 0
```

The first part, $`d(A, B)`$, translates as "the distance between points A and B." For example:

```
Home → School = 5 km
Home → School = -5 km?
```

Negative distance makes no sense in ordinary geometry.

Even 0 is allowed — and the second axiom explains exactly how.

### 2. Identity of Indiscernibles

This long name translates pretty simply:

**"The only thing that is zero units away from you is you."**

```math
d(A, B) = 0 \iff A = B
```

What does this mean? It means there's no way to move from point A to point B and have the distance come out to 0 — unless A and B are actually the same point. The only way to get a distance of 0 is to not move at all.

For example:

```
Chair → Chair = 0 meters - True
Chair → Table = 0 meters - False
```

Zero only ever happens when the two points are identical.

Now let's move on to the next rule.

### 3. Symmetry

In geometry, symmetry means:

**"Distance doesn't care which direction you measure it in."**

This simply means:

```
Home → School = 8 km
School → Home = 8 km
```

This has to hold. There's no reason the trip from school to home would somehow be 40 km — did we climb Everest twice on the way back? This rule is easy; we've already grasped the concept intuitively.

### 4. Triangle Inequality

The idea here is simple too.

Imagine going from home to the nearest bakery, and then to school:

```
Home ----- Bakery ----- School
```

Say:

```
Home → Bakery = 2 km
Bakery → School = 5 km
```

Adding them up:

```
Home -> School = 7 km
```

The direct distance can't be more than 7, because the direct route is always shorter than (or equal to) any indirect one — like going from home to the bakery and then to school.

The formula that says the same thing mathematically:

```math
\boxed{d(A, C) \le d(A, B) + d(B, C)}
```

The direct distance is always less than or equal to going through another point. This is exactly the idea behind a triangle: one side is never longer than the other two sides added together.

But why do we even care about these rules? Because if we invented a "distance" like:

```math
d(A, B) = -5
```

that would be impossible — it fails the positivity test immediately.

> [!CAUTION]
> There are exceptions, though — it always depends on the space. In Minkowski space, we actually do get negative "distances":
>
> ```math
> s^2 =-c^2t^2 + x^2 + y^2 + z^2
> ```
>
> Sometimes $`s^2`$ breaks the very first metric axiom — positivity. That's a good example of just how differently spaces can behave from one another.

## Isometries vs. General Transformations

This is an interesting topic, because it answers a question we've probably never actually asked ourselves:

**"What transformations change an object, and what transformations keep it the same?"**

Imagine this: you pick up a mug of coffee and rotate it 90°. Now let's answer some simple questions:

"Did the mug get bigger?" No.
"Did the mug get smaller?" No.
"Did any distance on the mug change?" No — because rotating it doesn't stretch, squish, or otherwise deform it. Every distance on its surface stays exactly the same.

This gives us our first idea: some transformations change how an object looks, while others only change where or how it's positioned.

But before we get into more of this, let's understand what a transformation actually is:

A transformation is simply a rule that moves every point to a new position.

Imagine we have these points:

```
Before

    ●

        ●

 ●
```

The transformation says: "Everyone, move over there!"

So the new positions might look like:

```
After

              ● 

                  ●

           ●
```

There are different types of transformations, but the simplest one is this — move everything 5 meters to the right:

```
Before

●
●
●
```
↓
```
After

      ●
      ●
      ●
```

Nothing changed except the position.

Another type of transformation is **rotation**, for example:

```
Before

●
●
●
```
↓
```
After

● ● ●
```

Again, the distances didn't change.

Another transformation is a **mirror reflection**. Think about this: you have a parabola:

```
  ●         ● 
   ●       ●
    ●     ●
      ●●● 
```

After reflection, it looks like:

```
      ●●● 
    ●     ●
   ●       ●
  ●         ●
```

Did the parabola get bigger? Nope. Did the points get farther apart from each other? Nope. All reflection did was flip the points.

So now we have three transformations:

| Transformation | Distance preserved? |
| -------------- | -------------------- |
| Translation | Yes |
| Rotation | Yes |
| Reflection | Yes |

> [!IMPORTANT]
> These are called **isometries**. From Greek: *iso* = equal, *metric* = distance. An isometry never changes distances.

If a transformation isn't isometric, it changes the shape of the points — they get stretched, shrunk, and so on.

Let's work through an example:

```math
A = (0, 0)
```

```math
B = (3, 4)
```

Now let's find the distance:

```math
d = \sqrt{(3 - 0)^2 + (4 - 0)^2} = \sqrt{9 + 16} = 5
```

Now let's rotate it by 90°:

```math
R = \begin{bmatrix} 0 & -1 \\ 1 & 0 \end{bmatrix}
```

Don't worry too much about where this matrix comes from for now — we'll just use it.

First, let's rotate A:

```math
R \begin{bmatrix} 0 \\ 0 \end{bmatrix} = \begin{bmatrix} 0 \\ 0 \end{bmatrix}
```

No surprise there.

Now let's rotate B:

```math
R \begin{bmatrix} 3 \\ 4 \end{bmatrix} = \begin{bmatrix} -4 \\ 3 \end{bmatrix}
```

The new points are:

```math
A = (0, 0)
```

```math
B = (-4, 3)
```

Now let's calculate the distance again:

```math
\sqrt{(-4)^2 + 3^2} = \sqrt{16 + 9} = 5
```

Same as before.

Now let's try a **non-uniform scaling** instead (stretching just one axis — x or y, not both; if we stretched both, that would be uniform scaling):

```math
R = \begin{bmatrix} 2 & 0 \\ 0 & 1 \end{bmatrix}
```

We stretch just the x side. Our new point:

```math
B = (3, 4)
```

becomes:

```math
B = (6, 4)
```

Now let's find the distance to B:

```math
\sqrt{6^2 + 4^2} = \sqrt{36 + 16} \approx 7.21
```

So originally we had 5, and now we have 7.21. That's *not* an isometry.

So, to sum up: an isometry preserves both distance and angle. But sometimes we only want to preserve the *angle*, not the distance.

That's called a **conformal transformation** — it usually doesn't preserve distance, only angle. This time, we don't care about distance changes at all; we only care about the angle.

Picture drawing a road at 90° on a balloon, then inflating the balloon. What happens? The balloon gets bigger, and the distance along the road changes — but the angle of the road is still 90°. It never changed.

Here's a small example. We have two points:

```math
A = (1, 0)
```

```math
B = (1, 1)
```

Let's say the angle between them is 45°. Now let's multiply everything by 2:

```math
A = (2, 0)
```

```math
B = (2, 2)
```

So... did the angle change? No, it didn't.

> [!NOTE]
> Isometries preserve both distance and angle. Conformal transformations only guarantee the angle stays the same — distance is free to change.
